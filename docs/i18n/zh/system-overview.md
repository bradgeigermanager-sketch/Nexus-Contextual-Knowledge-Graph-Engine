# 系统文档 — 简体中文

## 第一部分 — 技术说明

### 目标与范围
Nexus Contextual Knowledge Graph Engine 是一个正在开发的、以图为中心的信息环境，用于表示实体及其关系、保留来源与证据的上下文、验证导入的图数据，并通过高层级工件连接更大的知识区域。当前仓库包含一个单文件 HTML/React 应用，以及 JavaScript 验证模块、JSON 示例数据、模式定义、测试和 GitHub Actions 自动化流程。

### 核心层
1. **规范图：** 节点和边表示实体与关系。在受支持的导入/导出操作中，应尽可能保留标识符和属性。
2. **验证与数据交换：** 包括结构验证、已保存状态恢复、导入模式和针对不同格式的测试。CSV 支持带引号字段、转义引号和字段内换行。Cypher 导入器只支持有限的、基于正则表达式的子集，并非完整的 Cypher 解析器。
3. **来源与证据语料库：** 分别记录来源/作品、作者/出版者、主张和证据链接。证据可以指向节点、边、主张，或有向的“节点—边—节点”路径。来源、主张、证据立场、来源可靠性和抽取置信度是不同概念。
4. **高阶网络工件层：** 带版本的工件可以汇集指向节点、边、主张、来源、证据链接、上下文和其他工件的类型化引用。工件之间的链接可表达“包含”“重叠”“提供上下文”“反驳”或“依赖”等关系。目前“神经”指高阶网络建模概念；系统尚未实现经过训练的神经网络。
5. **测试与自动化：** Node.js 测试和 GitHub Actions 用于检查受支持的数据契约和示例数据。

### 来源追溯与不确定性
规范对象的身份必须与其是否属于某个工件区分开。适用时，应记录来源、版本、派生方法、输入快照、时间/上下文范围以及证据引用。相似度、相关性、边权重、置信度、来源可靠性、证据立场和事实真伪不能合并成一个分数。合成测试数据不是真实世界的引文或证据。

### 当前实现状态
当前工作分支包含图数据验证与测试、规范数据归档和导入示例、来源/证据语料库的模式与合成示例，以及高阶工件层的设计、模式、示例和完整性测试。面向用户的来源编辑器、工件浏览器、大规模来源采集和真实的神经网络/嵌入推理仍属于后续工作。声称最新提交已通过测试前，应检查 GitHub Actions 的当前状态。

## 第二部分 — 通俗说明

Nexus 是一个把信息整理成相互连接的部分的项目。节点代表事物或想法，边表示它们之间的关系。来源和证据帮助说明信息从哪里来。更大的相关信息组称为“工件”。

例如，一个工件可以把一份报告、一个主题、它们之间的关系，以及讨论这种关系的来源放在一起。工件还可以连接到其他工件。这样，人们就能浏览大量信息，而不必反复复制相同内容。

系统仍在开发中。目前已有部分数据检查、示例记录、模式定义和自动化测试。完整的可视化编辑器、自动发现信息群组，以及真正的神经网络分析尚未完成。标记为“合成”的示例只用于演示，并不证明现实世界的事实。

理解每条信息时，要分开考虑三个问题：记录写了什么？哪些来源支持它？我们对这种解释有多大把握？系统应保留分歧和不确定性，而不是将其隐藏。

## 新增的数据集加载步骤

加载器会一起读取图谱、来源、声明、证据链接、工件及工件之间的链接，检查引用并建立查找索引。缺失文件和无效引用会被明确报告，而不会被悄悄接受。这是数据加载与一致性检查功能，并不是能够学习或证明事实的神经网络。

简单来说，系统现在有一种可重复使用的方法来收集相互关联的记录，并在应用的其他部分使用它们之前，检查链接是否指向真实存在的记录。加载器尚未接入浏览器界面。


## 数据集加载器更新

加载器现在会把图谱、来源、声明、证据和高阶工件记录汇总为一个经过验证的数据快照，并建立查找索引。缺失文件和无效引用会被报告。这是数据一致性功能，不是学习或证明事实的神经网络；目前尚未接入浏览器界面。

## 更新：关系遍历

代码现在包含有界的语料遍历功能，可从带类型的引用开始，例如节点、边、来源、主张、证据链接或高阶工件。它会返回可到达的记录及其路径，并保留关系类型和可用的证据引用。遍历深度和结果数量均有限制。这是确定性的图遍历，不是神经网络推理，也不能证明主张为真；目前尚未接入浏览器界面。
